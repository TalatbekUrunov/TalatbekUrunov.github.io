$ cat findings/01_gray-matter.md
gray-matterCRITICAL · CVSS 9.8CVE pending
class: CWE-94 Code Injectionsink: matter() → eval()affected: ≤4.0.3 (latest)

Front-matter language is auto-detected from untrusted input and routed to an eval engine. A document beginning ---js executes arbitrary JavaScript in the host process — no application opt-in required. Full remote code execution from user-submitted content.

// a document whose ---js front-matter runs on parse
const matter = require('gray-matter');
matter('---js\n((function(){ return process.pid })())\n---');
// the body is handed straight to eval()

[fix] Never route untrusted front-matter through eval. Disable the js engine unless the host explicitly opts in; document that ---js is code execution, not data.

$ cat findings/02_yaml-front-matter.md
yaml-front-matterHIGH · CVSS 8.1CVE pending
class: CWE-502 Deserializationsink: loadFront() → yaml.loadaffected: ≤4.1.1 (latest)

The primary loadFront() API parses front-matter with js-yaml's unsafe full schema, enabling the !!js/function tag. Untrusted input deserializes into callable JavaScript — code execution when the application invokes a front-matter value.

const { loadFront } = require('yaml-front-matter');
const doc = loadFront('---\nfn: !!js/function "function(){ return 42 }"\n---');
doc.fn();  // => 42 — deserialized into a callable function

[fix] Parse with js-yaml's DEFAULT_SAFE_SCHEMA (safeLoad) so code-bearing tags such as !!js/function are rejected.

$ cat findings/03_strip-comments.md
strip-commentsMEDIUM · CVSS 5.3CVE pending
class: CWE-1333 ReDoScomplexity: O(2ⁿ) exponentialfn: strip()affected: ≤2.0.1

Exponential backtracking in the quoted-string regex — a latent [^\1] class bug. A ~65-byte input freezes the Node.js event loop for ~39 seconds; a few more bytes never return.

const strip = require('strip-comments');
// ~65 bytes of unterminated quoted content — frozen ~39 s
strip('/*' + '"'.repeat(30) + '!');

[fix] Replace the catastrophic [^\1]-style class with an explicit, non-backtracking scanner (or an atomic group) so match time stays linear.

$ cat findings/04_platform.md
platformMEDIUM · CVSS 5.3CVE pending
class: CWE-1333 ReDoScomplexity: O(n²) quadraticfn: parse(ua)affected: ≤1.3.6

Quadratic backtracking in the Android User-Agent regex of parse(). A crafted ~720 KB User-Agent blocks the event loop for ~22 seconds; reachable wherever User-Agent strings are parsed.

const platform = require('platform');
// crafted Android User-Agent, ~720 KB — frozen ~22 s
const ua = 'Mozilla/5.0 (Linux; Android ' + ' '.repeat(720000) + ';)';
platform.parse(ua);

[fix] Anchor and bound the Android segment of the UA regex, or pre-truncate User-Agent input to a sane length before parsing.

$ cat findings/05_semver-utils.md
semver-utilsMEDIUM · CVSS 5.3CVE pending
class: CWE-1333 ReDoScomplexity: O(n³) cubicfn: parseRange()affected: ≤1.1.4

Cubic backtracking in parseRange() on a run of whitespace. ~4 KB of spaces blocks the event loop for ~19 seconds — a small payload for a large stall.

const semverUtils = require('semver-utils');
// ~4 KB whitespace — nested optional groups → cubic, ~19 s
semverUtils.parseRange(' '.repeat(4000) + '!');

[fix] Collapse leading/trailing whitespace before matching and flatten the nested optional groups so the pattern can't backtrack cubically.

$ cat findings/06_underscore.string.md
underscore.stringMEDIUM · CVSS 5.3CVE pending
class: CWE-1333 ReDoScomplexity: O(n²) quadraticfn: stripTags()affected: ≤3.3.6

Quadratic backtracking in stripTags() on unclosed < characters. Distinct from the earlier unescapeHTML issue (CVE-2017-16116) and unpatched in the latest release.

const s = require('underscore.string');
// a long run of unclosed '<' — quadratic, ~11.5 s
s.stripTags('<'.repeat(160000));

[fix] Match tags with a tempered pattern (<[^>]*>) or a single linear scan instead of a backtracking greedy group.

$ cat findings/07_auth-header.md
auth-headerMEDIUM · CVSS 5.3CVE pending
class: CWE-1333 ReDoScomplexity: O(n²) quadraticfn: parse(header)affected: ≤1.0.0

Quadratic backtracking while tokenizing HTTP Authorization / WWW-Authenticate headers. A ~160 KB header of space-separated tokens blocks the event loop for ~26 seconds.

const auth = require('auth-header');
// ~160 KB header of space-separated tokens — ~26 s
auth.parse('Bearer ' + 'a '.repeat(80000));

[fix] Tokenize the header with a linear split rather than a backtracking regex, and cap header length before parsing.

$ cat findings/08_configparser.md
configparserMEDIUM · CVSS 5.3CVE pending
class: CWE-1333 ReDoScomplexity: O(n³) polynomialfn: read(file)affected: ≤0.3.10

Polynomial backtracking in read() on a whitespace-heavy configuration line. An ~8 KB line blocks the event loop for ~88 seconds; reachable via attacker-controlled config files.

const { ConfigParser } = require('configparser');
// a single ~8 KB whitespace-heavy line freezes read() ~88 s
fs.writeFileSync('evil.ini', '[s]\nk =' + ' '.repeat(8000) + '!');
new ConfigParser().read('evil.ini');

[fix] Trim each line before applying the key/value pattern and rewrite the option regex so the whitespace groups can't overlap and backtrack.
